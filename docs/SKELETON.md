## 0. Главный принцип

**Латентность важнее всего.** Текущий путь «фраза кончилась → whisper → LLM целиком
→ XTTS целиком → звук» даёт 6–12 с тишины. Цель — ≤2–3 с до первого звука за счёт
стриминга на всех этапах (LLM уже умеет `generate_stream` — пайплайн его не
использует, это бесплатная победа).

## 1. Слой УШЕЙ (требования 3, 8, 9, 10, 11)

### 1.1. Аудио-хаб `audio/` (➕ новый модуль)
Два независимых канала в один STT:
- **микрофон** — уже есть (stt/stt_module.py, sounddevice);
- **loopback (WASAPI loopback)** — весь звук системы = созвон (друг из Discord и т.п.).
  sounddevice умеет `sd.WasapiSettings(loopback=True)` — БЕЗ новых библиотек.
Каждый транскрипт помечается источником: `source=mic` / `source=loopback`.
STT превращается из «микрофонного модуля» в многоканальный: `STTModule` →
`add_channel(name, device_kind)`.

### 1.2. Фильтр адресации «ушами» `ears/` (➕)
Правило 11: **слышит всегда, отвечает только на обращение по имени.**
- Вся транскрипта проходит через гейт: regex по формам имени
  («Нимфея, Нима, Ним, Нимуль, нимфея а …») + дешёвый LLM-классификатор-резерв
  для хитрых случаев (1 токен, num_predict=8, не тормозит).
- Обращение → пайплайн (ответ). Не обращение → НЕ теряется: пишется в память
  как «подслушанное» (пониженная роль) + feeds движку инициативы.
- На.loopback-канале — то же правило: отвечает, только когда друг зовёт её по имени.

### 1.3. Голосовая идентификация `voice_id/` (➕)
- `resemblyzer` (CPU, лёгкий, без VRAM): вектор embedding на каждую фразу.
- Энроллмент: Кизил (микрофон-канал = владелец, имя из memory.user_context) и
  все, кто говорил в loopback — по 10–20 с чистой речи; профиль хранится в
  `memory.people[].voice_embedding`.
- Результат: каждая реплика знает «кто сказал» даже без имени → требование 9,
  и обращение по имени к собеседнику → требование 10.

## 2. Слой МОЗГА (требования 2, 5, 6, 13, 16, 17, 18, 19, 20, 21)

### 2.1. Стриминговый пайплайн (🔧 главный рефактор pipeline/)
```
транскрипта → ears(адресация?) → LLM stream (уже есть!)
    → резать на предложения по токенам
    → первое предложение сразу в TTS (синтез+проигрывание)
    → LLM продолжает, TTS синтезирует очередь предложений
```
- `pipeline._respond` → на стрим; `tts.speak` → `speak_stream` (см. 4.1).
- Перебивание (уже есть) работает и на стриме: флаг стопа гонится по всей цепочке.
- Один worker на реплику — сохранить (не перемешивать ответы).

### 2.2. Нити разговора `pipeline/threads` (➕ требование 19)
Пайплайн помнит «открытые хвосты»: {задан ли вопрос, кому, когда, что сказала}.
Watchdog (таймер 20–40 с, тихо у обоих каналов):
- задала вопрос, ответа нет → переспросить (варианты из persona);
- сказала, реакции нет → повторить с претензией («эй, ты оглох?»);
- максимум 2 хвоста, тон эскалирует, потом хвост закрывается.
Хвосты живут в памяти пайплайна + короткая сводка в промпт («ты ждёшь ответа на…»).

### 2.3. Интернет `web/` (➕ требование 16)
- `ddgs` (DuckDuckGo, без API-ключа) — поиск, топ-5 сниппетов.
- Триггеры: (а) LLM явно просит тегом `[ПОИСК: запрос]` в первом ходе →
  пайплайн ищет и делает второй ход с результатами (протокол простых тегов —
  3b-модель функции не тянет); (б) правило: Нима спросила — ответа нет N минут →
  сама ищет и приносит результат (связка с нитями 2.2).

### 2.4. Анти-галлюцинации и анти-повтор (🔧 требование 17)
- В persona/промпт: «отвечай только на ПОСЛЕДНЕЕ сообщение; не выдумывай факты —
  не знаешь, так скажи или [ПОИСК]».
- Дедуп: новый ответ сравниваем с последними 3 ответами (пересечение токенов);
  совпадение >80% → один авто-реген с повышенным repeat_penalty (ручной !regen уже есть).
- Причина галлюцинаций v13.1.0 (мусор в фактах) уже вычищена — не возвращать её:
  новые факты записывать только через осмысленное извлечение, не сырыми репликами.

### 2.5. Инициатива `initiative/` (➕ требование 18)
Тихий планировщик: если N секунд нет диалога (порог больше хвостов 2.2 —
например 3–5 мин) и никто не говорит:
- случайный источник: факт из веб-кэша (в фоне копим очередь интересного),
  история из памяти («а помнишь, как ты…»), вопрос по контексту последних тем
  (ключевые слова последних реплик → поиск похожей темы);
- говорим через пайплайн (та же цепочка TTS→аватар), пишем в память,
  после реплики инициативы заводим хвост (2.2) — живой человек.
- Приоритет НИЖЕ пользователя: любой вход от человека мгновенно отменяет реплику инициативы.
- ✅ v14.4.1: инициативы АДРЕСНЫЕ — `_proactive` выбирает случайного
  присутствующего (2.8, `pick_addressed()`; Кизилл с приоритетом) и
  адресует реплику по имени.

### 2.5.1. Маршрутизатор адресата (✅ v14.4.1, `ears` + `pipeline._route_addressee`)
Реплика в комнате адресуется: **ей / Кизиллу / третьему / никому**. Слои от
дешёвого к дорогому: словарь (звательное имя в начале; её имя в тексте) →
контекст (хвост-вопрос ждёт этот голос; окно диалога 12 с после её реплики
конкретному человеку) → LLM-микро-классификация (только неоднозначные
вопросительные ≤160 зн: НИМА/ИМЯ/НИКТО). Адресовано не ей → она молчит,
реплика в память с адресатом (`stt:overheard:Кизилл`), говорящий — в presence.
Режим: `NIMA_EARS_MODE=smart|strict`.

### 2.6. Память v3 `memory/` (✅ v14.3.6, требования 5, 13)
Файл не режется (требование 13 соблюдено); доступ улучшен:
- schema v3: у dialog-entry есть `speaker` (из voice_id 1.3) и `channel`;
- **RAG ГИБРИД РАБОТАЕТ**: recall = пересечение токенов + 2×косинус эмбеддингов.
  Эмбеддер — Ollama `nomic-embed-text` (нужен `ollama pull nomic-embed-text`!),
  инкрементальный индекс `cache/embeddings.jsonl`, фоновый воркер (пачки по 32)
  доиндексирует dialog+facts сам. Внимание v14.3.6: без скачанного эмбеддера
  RAG молча деградирует в токеновый поиск (лог: «векторный индекс: 0 векторов»);
- API `memory.query(кто, когда, текст)`, `person_names()`,
  `people_with_embeddings()` / `set_person_embedding()` (голоса) —
  «память о человеке» постоянна в people-слое memory.json;
- Ограничения лимитов (25 фактов/14 ходов в промпт) — лимит контекста 8192,
  менять только вместе с num_ctx.

### 2.7. Персонаж (✅ v14.4.1, требование 21)
- НЕ стерилизовать (правило 9 AGENT_ACTION_PLAN): пошлость и чёрный юмор без
  табу на темы (взрослый тон = банворды рантайма, не персона).
- **Анти-ассистент**: жёсткий блок-запрет («чем могу помочь», «рада помочь»,
  предложение услуги в конце реплики) → живая реакция вместо услуги.
- **Создатель нетранзферный**: `CREATOR_NAME` (core/config, env
  `NIMA_CREATOR_NAME`, дефолт «Кизилл») — единственный источник; персона явно
  запрещает признавать создателем кого-либо ещё («я тебя создал» → осадить).
- Словарь комьюнити: подписчики = «сабы», люди в чате = «чатерсы»;
  коронные фразы заданы в персоне.

### 2.8. Настроение и присутствие (✅ v14.3.2–v14.4.1)
**Настроение `pipeline/mood_state.py`** — устойчивое состояние между репликами:
- тег `[ЭМОЦИЯ: …]` от самой Нимфы = сильный источник (держится 3 хода);
- слова пользователя «заражают» (2 хода), только пока она сама в норме;
- `tick()` после каждого ответа — затухание к normal;
- текущее настроение получает **system-промпт** («продолжай в нём») →
  LLM генерирует текст в настроении, и голос (SSML-prosody), и лицо аватара
  берут то же состояние — текст/тон/лицо согласованы.

**Присутствие `pipeline/presence.py`** — кто сейчас «в комнате» (сессия):
- голос распознан (voice_id) → человек тут;
- прощание («я пошёл», «спокойной ночи»; союз «пока» защищён негативным
  lookahead) → вышел; чужая реплика «X ушёл» → X вышел;
- нить закрыта без ответа после 3 переспросов (`threads.on_tail_dropped`) →
  человека нет;
- присутствующие идут в system-промпт («кто с тобой говорит; кого нет —
  не адресуй»);
- **инициативы адресные**: `_proactive` выбирает присутствующего
  (`pick_addressed()`, Кизилл с приоритетом) и адресует реплику по имени.


### 2.9. Зрение: экран компьютера (✅ v14.5.0, `vision/`)
Глаза — **ТА ЖЕ gemma3:4b** (мультимодальная, `llm.generate_vision`, images
в /api/chat). Второй VLM НЕ заводим: 6 ГБ VRAM не вмещают две модели, своп =
десятки секунд тишины. Бюджет взгляда ~2–4 с (захват <0.3 с + короткая генерация).
- **Фоновые наблюдения**: тихо (≥ `VISION_MIN_QUIET_SEC`) и она молчит →
  раз в `VISION_INTERVAL_SEC` скриншот (896px, JPEG) → описание в 1–2
  предложениях; busy_check (говорит/worker жив) откладывает взгляд — зрение
  никогда не конкурирует с репликой за Ollama;
- **режим просмотра** (видео/игра): тишина ≥ `VISION_WATCH_QUIET_SEC` + кадры
  меняются (детектор движения по мини-кадрам) → интервал ужимается до
  `VISION_WATCH_INTERVAL_SEC`;
- **память увиденного в 3 слоя**: контекст (последние наблюдения в каждом
  system-промпте, `prompt_builder.vision_summary`), постоянная память
  (факт «Видела на экране: …», троттлинг `VISION_FACT_MIN_SEC`), RAG
  (факт индексируется эмбеддером → «куда я положил камень» найдётся);
- **реплики про экран**: «что я делаю», «где кнопка», «куда я положил» —
  НЕ адресованы ей, но гейт пропускает (`is_screen_request`) и пайплайн
  снимает СВЕЖИЙ кадр (`describe_now`) в промпт;
- **не разглядела → вопрос**: модель отвечает с «ВОПРОС: …» → уходит в
  инициативы (она сама переспросит у комнаты);
- **инициативы от увиденного**: `_proactive` с шансом берёт свежее
  наблюдение темой (vision/vision_question);
- «зрение минус шесть» (`persona.VISION_SENSE`): протокол честного зрения —
  не выдумывать детали, не разглядела — спросить.

### 2.10. Слышимость и бесшовные перебивания (✅ v14.5.0)
**Матрица слышимости** (я слышу Ниму и людей · люди и Нима слышат меня ·
все слышат Ниму · Нима слышит всех):
- пока она говорит: микрофон в режиме перебивания (`set_barge`, порог выше),
  loopback НЕ глушится, а копит буфер (`stt.set_defer`); сразу после её
  реплики буфер распознаётся → пайплайн; её собственный голос из буфера
  выкидывает **эхо-фильтр** (пересечение с монологом ≥0.6 → игнор);
- TTS: у каждого потока свой stop-флаг (`stop()` — всё, `stop_previous()` —
  только предыдущий), счётчик активных потоков (`active_streams`).

**Бесшовная передача слова** (`_handover` + `pre_play` в `speak_stream`):
- жёсткий триггер («стоп!») — молчит мгновенно;
- обращение к ней / реплика, связанная с монологом, — она ДОГОВАРИВАЕТ,
  пока новый ответ синтезируется; глушение старой речи происходит ровно
  перед первым звуком новой — без мёртвой тишины на генерацию;
- посторонняя болтовня и эхо — игнор, она продолжает.

### 2.12. Слои жизни (✅ v14.7.0)
- **Активное окно** (`vision/`): `active_window_title()` (ctypes) — заголовок
  foreground-окна в запросе описания кадра: она знает, во что играют/смотрят,
  а не «видит экран». Выключение: `NIMA_VISION_WINDOW=0`.
- **Watchdog** (`watchdog/`): раз в 15 с живость capture/recognizer-потоков
  STT (мёртвые → `STTModule.restart()`), раз в 60 с — Ollama; журнал проблем
  для debug menu.
- **Дневник** (`diary/`): после 03:00 — LLM сжимает вчерашний день в
  воспоминание от первого лица → факт «Дневник за …» (контекст + RAG);
  идемпотентно по `cache/diary_last.txt`.
- **Хоткеи** (`core/hotkeys.py`, RegisterHotKey): Ctrl+Alt+D — взгляд на
  экран вслух, M — мьют ушей, W — режим просмотра авто/вкл/выкл, S — молчать.
- **Ритм дня** (`persona.time_sense`): блок времени суток в system (ночь —
  сонная, вечер — разговорчивая).
- **Affinity** (`memory.adjust_affinity`): отношение −100..+100 на человека
  (тепло +2, грубость −4, раз в минуту; создателю не меняется), не-нейтральные
  в промпт.

## 4. Слой ГОЛОСА (✅ v14.3.x, требования 1, 12, 20)

### 4.1. Движок: Silero v5 (решено, XTTS/клоны отклонены)
- `tts/tts_module.py`, бэкенд **silero** по умолчанию: torch.hub
  `snakers4/silero-models`, модель **v5_5_ru** (фолбэк v4_ru встроен),
  голос **baya**, синтез **48 кГц** (24 кГц = «металл» на согласных),
  RTF 0.02–0.4 на CPU, ноль VRAM.
- **Эмоции SSML**: rate ТОЛЬКО словами (fast/slow — проценты в rate сломаны
  в модели!), pitch процентами; итоговый pitch = база (+25%, «пикми-тян»,
  `NIMA_TTS_PITCH`) + эмоция, жёсткий потолок +35% в `_pitch_total` (выше
  Silero v5 «плывёт»). Настроение → rate/pitch: `SILERO_EMOTION_RATE/PITCH`.
- Интонации «?»/«!» Silero ставит сам по пунктуации (пунктуация доходит
  нетронутой).
- Синтез во время проигрывания: `torch.set_num_threads(cores−2)` — иначе
  недогружается аудиобуфер sounddevice (треск).

### 4.2. Клон голоса (требование 12) — закрытый вопрос на 6 ГБ
Замеры при живой gemma3:4b (свободно ~2 ГБ): Fish Speech 1.5 RTF 2.9 +
«звуки ада» zero-shot; XTTS RTF 0.55–1.0 и +1.7 ГБ; Chatterbox RTF 1.4 и
+2.1 ГБ; F5-TTS RU сломан (RTF 9–18). Вывод: качественный эмоциональный клон
= карта 12+ ГБ; целевой движок на будущее — dots.tts. Ручное включение
неудавшихся: `NIMA_TTS_BACKEND=xtts|chatterbox`.

### 4.3. LoRA-мозг (v14.4)
- Стилевой датасет `training/make_style_dataset.py` → `dataset_style.jsonl`
  (1184 примера, ручные сцены, без живой памяти; manual_pairs ×5).
- Обучение: `training/nima_lora_colab.ipynb` (Colab, T4, unsloth,
